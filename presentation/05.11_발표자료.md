# 1. 이번주 진행 사항

---

### 1-1. DeepFilterNet 노이즈 제거 모듈 구현

- DeepFilterNet3 기반 노이즈 제거 래퍼 모듈 구현 (`DeepFilterNet/denoise.py`)
- 기존 파이프라인이 16kHz 기준인 반면 DeepFilterNet은 48kHz에서 동작하므로, 내부적으로 16kHz → 48kHz 업샘플 → 처리 → 16kHz 다운샘플 과정을 자동으로 수행하도록 설계
- 모델을 매 호출마다 재로드하지 않도록 싱글톤 패턴 적용 (첫 호출 시 1회만 로드)
- 입출력 계약: `float32 numpy, mono, 16kHz` — 기존 파이프라인 모듈과 동일한 인터페이스 유지

### 1-2. DeepFilterNet 단독 테스트 스크립트 작성 및 검증

- 실제 녹음 파일(Red_noisy.m4a)을 입력으로 노이즈 제거 전후 WAV 비교 스크립트 작성 (`DeepFilterNet/denoise_test.py`)
- 테스트 결과: RMS **-27.2 dBFS → -33.5 dBFS** (노이즈 성분 제거 확인)
- 원본 / 제거 후 WAV 파일로 저장하여 청각적 품질 비교 가능

### 1-3. 전체 통합 파이프라인 구성

- 오디오 입력 → DeepFilterNet → VAD → Whisper STT → Command Parser → Task ID 전체 흐름을 단일 스크립트로 통합 (`pipeline/pipeline.py`)
- 각 모듈 폴더(`DeepFilterNet/`, `Whisper/`)를 `sys.path`로 연결하여 모듈 독립성 유지

### 1-4. GitHub 저장소 구축 및 프로젝트 구조 정리

- GitHub 개인 계정에 `Indursty_project` 저장소 생성 및 연결
- 오타 중복 파일(`pipline.py`), VAD 생성 출력물(`*_vad.wav`) 제거
- 모듈별 커밋으로 변경 이력 관리 (`DeepFilterNet`, `pipeline`, `docs` 분리)

# 2. 이번 주 발생 이슈 및 해결

---

### 2-1. DeepFilterNet ↔ 파이프라인 샘플레이트 불일치

**현상**

DeepFilterNet3은 내부적으로 48kHz 오디오를 요구하는데, 기존 파이프라인 전체가 16kHz 기준으로 설계되어 있어 직접 연결 시 오디오 길이 및 품질 불일치 발생

**원인**

DeepFilterNet의 `df_state.sr()`이 48000을 반환하며, 16kHz 입력을 그대로 넘기면 모델 내부에서 샘플 수 기반 처리 오류 발생

**해결**

`denoise()` 함수 내부에서 `torchaudio.functional.resample`을 통해 16kHz → 48kHz → 16kHz 변환을 자동 처리하도록 구현. 외부에서는 기존과 동일하게 16kHz float32 배열을 입출력으로 사용

### 2-2. DeepFilterNet 적용 시 오히려 명령어 인식률 저하

**현상**

CER·명령어 인식률 비교 평가(`evaluation/eval.py`) 결과, DeepFilterNet 미적용 시 인식률 80%(4/5)인 반면 적용 시 60%(3/5)로 오히려 하락

| 파일 | DFN 꺼짐 | DFN 켜짐 |
|------|----------|----------|
| Red_noisy.m4a | O (CER 0.429) | O (CER 0.429) |
| Yellow_noisy.m4a | X (CER 0.714) | X (CER 0.714) |
| voice_test.m4a | **O (CER 0.286)** | **X (CER 0.571)** |
| voice_test_yellow.m4a | O (CER 0.429) | O (CER 0.429) |
| yellow_dongmin.m4a | O (CER 0.571) | O (CER 0.429) |

**원인**

DeepFilterNet은 노이즈가 있다는 전제로 항상 음성 신호를 처리한다. 테스트에 사용된 녹음 파일(`voice_test.m4a`)이 상대적으로 조용한 환경에서 녹음된 경우, 모델이 음성 주파수 일부를 노이즈로 잘못 판단하여 제거함으로써 STT 입력 품질이 오히려 저하된다. 즉, **소음이 적은 환경에서는 DeepFilterNet이 독이 되는 상황**

**해결 방향**

현재 테스트 데이터는 실제 소음 환경 데이터가 아니므로 DeepFilterNet의 효과를 제대로 측정할 수 없음. 공장·실외 등 배경 소음이 심한 환경에서 직접 녹음한 데이터로 재검증 필요

### 2-3. 리샘플링 체인으로 인한 아티팩트 발생 가능성

**현상**

DeepFilterNet은 48kHz 기준 모델이나 파이프라인은 16kHz로 동작하므로, 처리 과정에서 16kHz → 48kHz → 16kHz 이중 리샘플링이 발생함. 이 과정에서 미세한 음질 열화가 누적될 수 있음

**원인**

업샘플링 시 보간(interpolation)으로 생성된 가상의 고주파 성분을 DeepFilterNet이 처리한 뒤, 다운샘플링 과정에서 앨리어싱(aliasing) 아티팩트가 남을 수 있음. 원본에 없던 왜곡 성분이 STT 입력에 영향을 줄 가능성 존재

**해결 방향**

파이프라인 전체를 48kHz로 통일하거나, DeepFilterNet 16kHz 지원 경량 모델(DeepFilterNet2 16kHz variant) 사용을 검토

# 4. 음성 명령 파이프라인 구성 및 진행 현황

---

음성 명령 파이프라인은 총 7단계로 구성되며, 현재 6단계까지 구현이 완료된 상태.

### 단계별 구성 요약 (파이프라인)

| 단계 | 모듈 | 설명 | 상태 |
|------|------|------|------|
| 1단계 | 음성 입력 | 실시간 마이크 스트리밍 | 미완 |
| 2단계 | DeepFilterNet | 신경망 기반 노이즈 제거 | **오류 수정중** |
| 3단계 | Wake Word | 특정 단어 감지 시 시스템 활성화 | 미완 |
| 4단계 | Silero VAD | 발화 구간만 추출, 묵음 제거 | 완료 |
| 5단계 | Whisper STT | 정제된 음성 → 텍스트 변환 | 완료 |
| 6단계 | Command Parser | 텍스트 → 명령어 ID 변환 | 완료 |
| 7단계 | Task ID 전달 | Task ID → 로봇 전달 (추후 구현) | 부분 완료 |

전체 과정 중 약 **60% 달성** (7단계 중 4, 5, 6단계 완료 / 2·7단계 부분)

### 진행 사항 요약

- 완료: 3단계 (4, 5, 6단계) / 부분 완료: 2·7단계
- 다음 주 예정: 3단계 Wake Word (KWS)
- 이번주 산출물: DeepFilterNet 노이즈 제거 모듈 완성 및 전체 통합 파이프라인 구성
